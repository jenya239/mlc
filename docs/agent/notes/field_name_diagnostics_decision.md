# Имя поля в диагностике, индекс в байткоде и в куче

Доступ к полю записи — `GET_PROP` / `SET_PROP`. Индекс поля — операнд `u8` слова инструкции. Объект записи на куче хранит значения полей по этому индексу и не хранит имя.

Код лоуэра и кучи этим шагом не менялся.

## Формат записи на куче не меняется

`heap_in_place_alloc_record` (`script_vm/heap_alloc.mlc`) вызывает `heap_in_place_alloc_object` с `type_id = heap_type_record()` (3), `object_flags = 0`, `shape_or_meta = 0`, `element_count = field_count`, `size_class = 2`.

Слот `HeapSlot` (`script_vm/heap_types.mlc`):

- `header.type_id` — 3
- `header.gc_flags` — 0 при выделении
- `header.object_flags` — 0
- `header.shape_or_meta` — 0, не идентификатор типа и не имя поля
- `child` — nil
- `element_start` / `element_count` — начало и число значений в `element_arena`
- элементы — значения полей в порядке объявления, по индексу `0 .. field_count - 1`

Имени поля в заголовке и в элементах нет. Это и остаётся форматом. В `shape_or_meta` имя не записывается.

## Индекс в слове инструкции не меняется

`instruction_encode` кладёт операнды в байты 8..15, 16..23 и 24..31 (`script_vm/bytecode.mlc`). `fits_u8` — диапазон 0..255.

- `NEW_RECORD`: A — регистр, B — число полей
- `GET_PROP`: A — назначение, B — регистр записи, C — индекс поля; чтение в `executor_read_record_field` идёт по `decoded.c`
- `SET_PROP`: A — регистр записи, B — индекс поля, C — регистр значения; проверка границ сравнивает `decoded.b` с `element_count`

Дизассемблер печатает `#` и число индекса. Имя в слово инструкции не пакуется.

## Таблица диагностики

Лоуэр уже резолвит имя в индекс: привязка `*record*` + имя типа + `#` + имя поля → индекс (`record_field_binding` в `script_vm/lower/lower_records.mlc`). Исполнение `GET_PROP` / `SET_PROP` эту привязку не читает.

Обратное соответствие для текста диагностики — отдельная таблица лоуэра, не слот кучи и не операнд опкода:

- ключ: имя типа записи и индекс поля (`u8`)
- значение: имя поля

Сообщение, которому иначе доступен только индекс, берёт имя из этой таблицы. Исполнение чтения и записи поля таблицу не читает и формат слота не меняет.

Поле, которого в типе нет, индекса не имеет. Отказ остаётся лоуэрным (`unknown_field` в `read_named_field`). В сообщение входит имя из источника, не число индекса. Таблица для этого отказа не подменяет имя: смотреть в ней нечего.
