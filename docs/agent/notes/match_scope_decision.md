# Срез `match` для лоуэра

Шаги 231–248 принимают только паттерн, который стоит непосредственно в рукаве `MatchArm`. Источник узлов — `docs/agent/notes/match_frontend_survey.md`.

## Включено

| Форма | Узел | Шаги |
|---|---|---|
| литерал `i32` | `PatternInt(i32, Span)` | 232–235 |
| литерал `bool` | `PatternBool(bool, Span)` | 236–237 |
| wildcard `_` | `PatternWild(Span)` | 232, 235 |
| биндинг переменной | `PatternIdent(string, Span)` | 238–239 |

Биндинг на верхнем уровне рукава — catch-all: после него другие рукава недостижимы (шаг 239). Для `i32` рукав `_` обязателен, полное перечисление значений не входит в срез (шаг 235). Для `bool` wildcard не обязателен, если есть и `true`, и `false` (шаг 237).

## Исключено

Деструктуризация записи и вложенные паттерны в 231–248 не принимаются.

| Форма | Узел | Что делают шаги 231–248 |
|---|---|---|
| деструктуризация записи | `PatternRecord(string, [Shared<Pattern>], Span)` | 246–247 дают именованный отказ, не приём |
| вложенный паттерн | элемент списка внутри `PatternCtor`, `PatternRecord`, `PatternArray`, `PatternTuple` или `PatternOr` | нет шага приёма |

Вложенный — любой `Pattern`, который не является единственным паттерном рукава. `Ok(value)` — `PatternCtor` с вложенным `PatternIdent` — вне среза. Голый верхний `PatternIdent` в таблице «Включено» вложенным не считается.

Вне среза также остаются формы, которые frontend уже строит, но 231–248 не принимают: `PatternStringLit`, `PatternCtor` (и без вложенных паттернов), `PatternOr`, `PatternArray`, `PatternStr`, `PatternUnit`, guard `if` перед `=>` (`MatchArm.has_guard`).
