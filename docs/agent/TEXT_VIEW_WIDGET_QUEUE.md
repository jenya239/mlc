## Решения

| id | Ответ |
| --- | --- |
| D1 | Потолка размера файла нет. Документ — куски: загруженные строки либо непрочитанный промежуток (смещение и длина, без разбора на строки). Окно запрашивает диапазон и дочитывает его до конца строки. Остальной файл строками не становится. `to_bytes` всего файла при живом промежутке отказывает. Битый UTF-8 в загруженном куске даёт `origin=lossy`. `origin=truncated` из-за размера нет. Размер в текущем ABI — `i32`: `file_byte_size` для файла больше 2 ГиБ − 1 байт возвращает −1, такой файл не открывается. Это предел ABI, не обрезка текста |
| D2 | Шейпер получает не больше 4096 байт одной строки, обрезка по границе графемы. Документ остаётся целым. Каретка и правка в нешейпленном хвосте отказывают |
| D3 | Кэш строк — `misc/textui/text_shape_cache.mlc`. `misc/gui/text_shaping.mlc` остаётся кэшем гарнитуры и одноразовым буфером HarfBuzz. Результат вызова копируется до следующего шейпинга. Ключ целого текста из `text_layout.mlc` для этого виджета не используется |
| D4 | Новый вид — `KindTextView`. Запись данных виджета лежит в `text_view_state.mlc`. В `store.mlc` добавляется только вариант и ветки `match`. Полная замена файла через `file_write_string` — только когда непрочитанных промежутков нет и `origin` не `lossy`. Пока промежуток жив, запись кладёт изменённые байты на их прежние смещения и не затирает непрочитанный хвост. Путь проходит отказ секретных имён и проверку jail галереи. Диалога нет. `workspace_files.mlc` и `misc/editor/` не вызываются |
| D5 | Перенос по ширине начинается на STEP=16. До него строка занимает один ряд, `wrap_px` в ключе равен 0. STEP=12 перенос не ждёт |
| D6 | Первый токенизатор — комментарии `//` и `/* */`, один цвет. Язык не выбирается |
| D7 | Номеров строк нет. STEP=7 идёт без колонки номеров |
| D8 | Стек undo — 64 записи. В этой очереди только вставка, Backspace, Delete и Enter. Ctrl+K/D/U/T/J, сдвиг строки, indent и тройной клик не переносятся |

## Инварианты

- Документ — куски. Загруженный кусок хранит строки с устойчивым `id` и `rev`. Непрочитанный промежуток хранит смещение и длину. Каретка стоит только в загруженной строке.
- `replace` возвращает `Edit` и не склеивает весь файл. Индекс смещений обновляется точечно.
- Undo хранит обратный `Edit`, не снимок всего текста. `KindTextField` не расширять: его undo — снимки.
- Ключ шейпинга строки: `line_id`, `rev`, шрифт, размер, `wrap_px`, `token_rev`, предел байт. Каретки, выделения, hover и прокрутки в ключе нет.
- Шейпятся строки видимого окна. Hover читает уже собранную строку.
- `lossy` не принимает правку и не пишется на диск. Непрочитанный промежуток не редактируется, пока его не подгрузили. Полная перезапись файла при живом промежутке запрещена.
- `misc/editor/` не открывать. Второй процесс галереи не запускать. `compiler/**` не трогать.
- `app.mlc` только собирает кадр. Файл `misc/textui/` не длиннее 400 строк.
- После шага, который меняет кадр, hover или попадание: `bash scripts/run_textui_hover_bench.sh`. Бюджет не поднимать: `hover_damage_min_us` ≤ 1000 и `hover_damage_min_us * 3 < hover_full_min_us`.
- Имена — полные английские слова. Отрицательное число в новом MLC писать как `0 - 1`. У каждого `if` свой `end`.

## Проверка

На каждом шаге:

```bash
ruby scripts/run_textui_file_size.rb
```

Плюс сборка и запуск нового unit-теста этого шага через `compiler/out/mlcc` и `compiler/build_bin.sh`.
Красный тест до кода должен падать по отсутствию названного поведения, а не по опечатке.
`scripts/regression_gate.sh` и холодная Ruby-сборка не нужны: `compiler/**` этот трек не меняет.

## Шаги

Статус: `pending`, пока шаг не сдан. В `verify` писать команду и код возврата.

### STEP=1 — документ из байт

status: done
verify: красный `tmp/text_document_unit/bin` → RUN:1. После разбора: `compiler/out/mlcc -o tmp/text_document_unit misc/textui/test/text_document_unit.mlc` → MLCC:0, `compiler/build_bin.sh tmp/text_document_unit tmp/text_document_unit/bin` → LINK:0, бинарь → RUN:0. `ruby scripts/run_textui_file_size.rb` → SIZE:0.

Красный тест: байты `a\nb\nc` дают три строки, терминаторы `lf`, `lf`, `none`, обратная сборка равна входу. Пустой ввод — одна пустая строка с терминатором `none`.

Минимум: один проход по байтам. Терминаторы `lf`, `crlf`, `cr`, U+2028, U+2029. Результат — один загруженный кусок, непрочитанных промежутков нет. Поля `origin` и `writable`.

Файлы: `misc/textui/text_line.mlc`, `misc/textui/text_document.mlc`, unit-тест.

### STEP=2 — байты не портятся

status: pending
решение: D1 закрыто

Красный тест: `\r\n`, `\r`, U+2028 и U+2029 возвращаются теми же байтами. Хвостовой перевод строки не добавляется. Невалидный UTF-8 даёт `origin=lossy`, сборка байтов отказывает. Документ с загруженным началом и непрочитанным хвостом не разбирает хвост на строки, правка начала не меняет длину хвоста, `to_bytes` всего файла отказывает. Потолка байт, после которого файл становится `truncated`, нет.

Файлы: `text_document.mlc` или `text_document_load.mlc`, если первый файл упирается в 400 строк.

### STEP=3 — смещение за логарифм

status: pending

Красный тест: `offset_of` и `line_of` взаимны. Смена длины первой строки в документе на 200 000 строк не портит далёкое смещение. Линейный пересчёт всех начал этот тест не принимает.

Минимум: дерево сумм с точечным обновлением и поиск индекса по `line_id`.

Файл: `misc/textui/text_line_index.mlc`.

### STEP=4 — правка возвращает Edit

status: pending

Красный тест: `replace` возвращает `Edit`. Чужие строки сохраняют `id` и `rev`. У затронутой `rev` растёт, `id` не переиспользуется. `map_offset` различает gravity. `invert` возвращает прежние байты.

Минимум: читать удалённый кусок из затронутых строк. Весь файл не склеивать. Индекс обновлять точечно.

Файлы: `misc/textui/text_edit.mlc`, `text_document.mlc`.

### STEP=5 — графема и слово

status: pending

Красный тест: слово в `ab cd`. Кластер `e` с акутом — одна граница. ZWJ, флаг, CJK и иврит не режутся. Повтор при том же `rev` не пересчитывает границы. Смена `rev` пересчитывает.

Файл: `misc/textui/text_graphemes.mlc`.

### STEP=6 — кэш шейпинга строки

status: pending
решение: D3 и D5 закрыты. `wrap_px` равен 0

Красный тест: три видимые строки дают три вызова `text_shaping_shape`. Повторный кадр — ноль. Смена каретки, hover и прокрутки — ноль вызовов.

Минимум: пул `line_id` → ключ, advance по кластерам, x границ графем, высота. Буфер шейпера копируется до следующего вызова.

Ключ: `line_id`, `rev`, шрифт, размер, `wrap_px`, `token_rev`, предел байт.

Файл: `misc/textui/text_shape_cache.mlc`.

### STEP=7 — видимые ряды

status: pending
решение: D7 закрыто, колонки номеров нет

Красный тест: документ на 5000 коротких строк после первого кадра шейпит только видимое окно. Колесо на одну строку шейпит одну входящую строку.

Минимум: якорь `{line_id, dy}`. Индекс строки из индекса документа. Виджет сам является вьюпортом. Высота «все строки × ряд» в layout не кладётся. Полоса рисуется после рядов. Оценка ширины только растёт.

Файлы: `misc/textui/text_view_state.mlc`, `misc/textui/text_view_paint.mlc`.
Проверка: hover bench, если кадр или попадание изменились.

### STEP=8 — открытие файла

status: pending
решение: D4 закрыто

Красный тест: файл из трёх строк открывается новым видом, не меткой. Число и высота строк списка файлов не меняются. Окно короче буфера оставляет непрочитанный промежуток, и строки из него не создаются.

Минимум: просмотр. Трёхстрочный файл — один загруженный кусок. Диапазон читается отдельно от `file_read_to_string`: сейчас такого чтения в ABI нет, его добавляет этот шаг. Граница куска совпадает с концом строки.

### STEP=9 — hover слова

status: pending

Красный тест: движение внутри слова не просит шейпинг. Смена слова красит ряды старого и нового слова. Точка на несобранной строке даёт пустой hover и не вызывает шейпер.

Минимум: токен `{line_id, rev, start, end}` на виджете. Подчёркивание — заливка поверх уже собранной строки.

Проверка: hover bench. Бюджет не поднимать.

### STEP=10 — каретка и выделение

status: pending

Красный тест: клик ставит позицию на графему. Влево и вправо шагают графемой. Вниз помнит `goal_x` и не теряет колонку на короткой следующей строке. Стрелка шейпит не больше строки назначения. Shift+вправо пишет диапазон глобальными байтами. Клик по метке каретку не двигает.

Прямоугольники выделения — набор диапазонов x на строке.

Файлы: `text_view_state.mlc`, `misc/textui/text_view_input.mlc`.

### STEP=11 — длинная строка

status: pending
решение: D2 закрыто

Красный тест: строка длиннее предела шейпится до границы графемы. Документ остаётся целым. Каретка и правка в нешейпленном хвосте отказывают.

### STEP=12 — клавиатура

status: pending
решение: D5 закрыто, перенос этот шаг не ждёт

Красный тест: символ шейпит одну строку каретки. Enter шейпит две затронутые, строки ниже сохраняют `id`. Backspace в начале строки шейпит одну, если результат виден. `lossy` клавишу игнорирует. Правок в непрочитанном промежутке нет.

### STEP=14 — запись на диск

status: pending
решение: D4 закрыто

Красный тест: при полном документе сохранение пишет его байты. `lossy` не пишется. Документ с непрочитанным хвостом не заменяет файл загруженным началом: на диск ложатся только изменённые байты по прежним смещениям. Диалога нет.

### STEP=15 — подсветка

status: pending
решение: D6 закрыто, только комментарии

Красный тест: токенизатор строки принимает `state_in` и отдаёт `state_out`. Совпавший `state_out` останавливает проход. Открытый блочный комментарий идёт по бюджету строк на кадр. Смена `token_rev` пересобирает одну строку. Hover токенизатор не вызывает.

Свежесть не сканируется от нулевой строки на каждом кадре.

Файл: `misc/textui/text_highlight.mlc`.

### STEP=16 — перенос и высоты

status: pending
решение: D5 закрыто

Красный тест: `wrap_px` входит в ключ. Число рядов абзаца берётся из его кэша. Смена ширины не создаёт новый документ. Несобранный абзац оценивается одним рядом. Поиск ряда по y не суммирует массив. Уточнение высоты выше якоря не двигает строку под якорем.

Якорь: `{line_id, subrow, dy}`.

Файл: `misc/textui/text_heights.mlc`.

### STEP=17 — пометки

status: pending

Не начинать, пока нет потребителя: диагностика или закладка. В Ruby хранилище пометок из виджета не вызывается.

Красный тест: применение `Edit` читает корзины только затронутых `line_id`. `token` снимается. `diagnostic` обрезается и сдвигается. `bookmark` — точка с gravity. Многострочная пометка — два якоря `{line_id, byte, gravity}`.
